# WB Stream auth flow

This document describes how a goloom operator wires a WB Stream room as
an inbound — the one-time webview ceremony required to capture
long-lived guest credentials, and the periodic re-auth required when
those credentials expire.

The audience is anyone who's setting up the goloom admin panel or
debugging an inbound that's stuck on `auth_required`.

## Background

`stream.wb.ru` runs a stock LiveKit SFU behind a custom gRPC-Web
gateway. To talk to that SFU we need a **roomToken** (LiveKit JWT,
issued by WB, expires in ~2 minutes). To mint a roomToken we need a
WB **accessToken** (long-lived guest JWT) plus the **Cloudflare/WB-AAS
cookies** (`_wbafp`, `x_wbaas_token`, `_wbauid`). Cloudflare's antibot
challenge gates the cookies; passing it from a Go HTTP client is at
best fragile and at worst impossible (Turnstile / canvas fingerprinting
can't be solved server-side).

The pragmatic answer is **manual webview**: the operator authenticates
once in a real browser, exfiltrates the tokens via a bookmarklet, and
hands them to goloom. Then goloom can mint roomTokens at will until
cookies expire. See [research notes](../scripts/bench/RESULTS-multiplex-meetings.md)
for the throughput numbers that justify going this route at all.

## Cookie lifetimes

Captured 2026-05-06 from a live session:

| Cookie / Storage           | Where                  | TTL          |
|----------------------------|------------------------|--------------|
| `_wbauid`                  | cookie, `stream.wb.ru` | ~365 days    |
| `x_wbaas_token`            | cookie, secure         | ~14 days     |
| `_wbafp`                   | localStorage entry     | session-ish  |
| `wb_auth_auth_slice.accessToken` | localStorage     | bound to cookies |

`x_wbaas_token` is the bottleneck: when it expires the operator has to
visit the WB site and pass Cloudflare again. Two weeks between manual
re-auths is comfortable for a small fleet.

## One-time setup (per inbound)

1. **Open WB Stream room in a browser** — `https://stream.wb.ru/room/<id>`.
2. **Click "Войти как гость"**, enter a display name, accept ToS,
   click "Продолжить", then "Подключиться". You're now in the room.
3. **Pin the bookmarklet** below to the bookmark bar. Click it on the
   room page. It pops up a textarea containing a JSON blob.
4. **Paste the JSON** into the goloom admin panel's "WB Stream → Auth"
   form for the inbound. Save.

## Bookmarklet

Drag this link to the bookmark bar (or copy the URL into a new
bookmark) — it's a vanilla `javascript:` URL. Clicking it on
`https://stream.wb.ru/room/<id>` will gather everything goloom needs.

```javascript
javascript:(async function(){
  try {
    const slice = JSON.parse(localStorage.getItem('wb_auth_auth_slice') || '{}');
    if (!slice.accessToken) throw new Error('no accessToken — are you signed in as guest?');
    const cookies = await cookieStore.getAll();
    const cookieHeader = cookies.map(c => c.name + '=' + c.value).join('; ');
    const earliest = Math.min(...cookies.filter(c => c.expires).map(c => c.expires)) || null;
    const blob = {
      accessToken: slice.accessToken,
      cookies: cookieHeader,
      cookies_expire_at: earliest ? new Date(earliest).toISOString() : null,
      captured_at: new Date().toISOString(),
      room_url: location.origin + location.pathname,
    };
    const ta = document.createElement('textarea');
    ta.value = JSON.stringify(blob, null, 2);
    ta.style.cssText = 'position:fixed;top:5%;left:5%;width:90%;height:80%;z-index:99999;font:12px monospace;background:#fff;color:#000;border:2px solid #4CD964;padding:8px';
    document.body.appendChild(ta);
    ta.select();
    document.execCommand('copy');
    alert('Tokens copied to clipboard. Paste into Goloom admin → Inbound → WB Stream auth.\n\nClick anywhere on the textarea to close.');
    ta.addEventListener('click', () => ta.remove());
  } catch (e) { alert('goloom-bookmarklet error: ' + e.message); }
})();
```

> ℹ️ The single-line `javascript:` form (paste-friendly into bookmark
> URL field) is auto-generated by `make bookmarklet`. The pretty
> version above is for readability.

## How goloom uses the captured blob

The admin handler accepts the JSON via `POST /api/admin/inbound/<id>/livekit/auth`
(exact path TBD by the new admin UI work). Internally it maps to:

```go
inbound.Spec.LiveKit = &inbound.LiveKitSpec{
    RoomURL:         blob.RoomURL,
    AccessToken:     blob.AccessToken,
    Cookies:         blob.Cookies,
    CookiesExpireAt: blob.CookiesExpireAt,
}
inbound.Spec.Transport = "livekit-wb-stream"
```

At every Connect, [internal/sfu/livekit.fetchRoomConnect](../internal/sfu/livekit/auth.go)
takes `AccessToken + Cookies` and POSTs to
`/api-room-manager/v2/room/<id>/connection-details` to mint a fresh
LiveKit `roomToken`. That token is then used for one
`lksdk.ConnectToRoomWithToken` call. Subsequent reconnects re-mint.

The admin panel surfaces `CookiesExpireAt` minus 24 h as an alert
threshold ("WB cookies expire tomorrow — please re-auth").

## Re-auth (every ~14 days)

Same flow as one-time setup; the new tokens overwrite the old ones in
`Spec.LiveKit`. No need to recreate the inbound, the WG keys and
endpoint stay the same — only the credentials rotate.

## Failure modes

| Symptom                                           | Likely cause                       | Fix                              |
|---------------------------------------------------|------------------------------------|----------------------------------|
| 401 from `connection-details` at Connect         | accessToken or cookies expired     | Operator re-runs bookmarklet     |
| 403 / Turnstile challenge in webview              | Cloudflare flagged the IP          | Wait, or use a different IP      |
| `lksdk.ConnectToRoomWithToken: invalid token`    | roomToken expired between mint and dial (very rare, <2s window) | Auto-retry on supervisor loop |
| `room disconnected` immediately after Connect     | SFU policy — likely guest-mode rate limit | Verify identity uniqueness; use a fresh guest-register |
